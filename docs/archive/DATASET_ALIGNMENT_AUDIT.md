# Dataset Alignment Audit (Rank / Points / Seed / A–B / Winner)

> Historical audit, archived 2026-11-10. The 558-row input named below is not
> the current committed demo dataset. Original findings are retained as evidence;
> use the [research plan](../research/RESEARCH_PLAN.md) for new experiments.

This report traces how the historical training CSV is generated and evaluates row-level and dataset-level consistency for **player_a/player_b/winner** and the associated **rank/points/seed** fields and derived diffs.

Audit inputs used here:
- Built CSV: `data/historical_2026_v3.csv` (558 rows)
- Builder: `scripts/build_historical_from_tml.py`
- Feature engineering: `model_features.build_match_features`
- Training loader: `model_train.load_historical_csv`
- Automated checks: `scripts/dataset_alignment_audit.py`

---

## 1. COLUMN LINEAGE

### A/B identity + label

| training field | source file / function | raw source columns | transform | final meaning |
|---|---|---|---|---|
| `player_a` | `scripts/build_historical_from_tml.py:tml_row_to_our_row` | `winner_name` / `loser_name` | if `swap=False`: `player_a=winner_name`; if `swap=True`: `player_a=loser_name` | the name assigned to slot A |
| `player_b` | same | `winner_name` / `loser_name` | if `swap=False`: `player_b=loser_name`; if `swap=True`: `player_b=winner_name` | the name assigned to slot B |
| `winner` | same | (implied by `winner_name`) | if `swap=False`: `"A"`; if `swap=True`: `"B"` | which slot won the match |

**Key property:** The builder *randomly chooses* `swap = random.random() < 0.5` per raw match row to ensure both `"A"` and `"B"` labels appear. This is **not** “mirroring”; it is **random A/B assignment**.

### Rank / points / seed in the built CSV

| training field | source file / function | raw source columns | transform | final meaning |
|---|---|---|---|---|
| `rank_a` | `tml_row_to_our_row` | `winner_rank` / `loser_rank` | `swap=False`: `rank_a=winner_rank`; `swap=True`: `rank_a=loser_rank` | rank of player in slot A |
| `rank_b` | same | `winner_rank` / `loser_rank` | `swap=False`: `rank_b=loser_rank`; `swap=True`: `rank_b=winner_rank` | rank of player in slot B |
| `points_a` | same | `winner_rank_points` / `loser_rank_points` | `swap=False`: `points_a=winner_rank_points`; `swap=True`: `points_a=loser_rank_points` | points of player in slot A |
| `points_b` | same | `winner_rank_points` / `loser_rank_points` | `swap=False`: `points_b=loser_rank_points`; `swap=True`: `points_b=winner_rank_points` | points of player in slot B |
| `seed_a` | same | `winner_seed` / `loser_seed` | `swap=False`: `seed_a=winner_seed`; `swap=True`: `seed_a=loser_seed` | seed of player in slot A (event seed) |
| `seed_b` | same | `winner_seed` / `loser_seed` | `swap=False`: `seed_b=loser_seed`; `swap=True`: `seed_b=winner_seed` | seed of player in slot B |

### Derived diffs used by the model

These are computed at **feature engineering time**, not stored in the CSV.

| feature | source | formula | meaning |
|---|---|---|---|
| `rank_diff` | `model_features.build_match_features` | \(rank\_diff = rank_B - rank_A\) | positive ⇒ A has better (lower) rank number |
| `log_points_diff` | same | \(\log(1+points_A) - \log(1+points_B)\) | positive ⇒ A has more points |
| `seed_diff` | same | \(seed\_diff = seed_B - seed_A\) | positive ⇒ A has better (lower) seed |

## 2. FORMULA VERIFICATION (ground truth)

From `model_train.load_historical_csv`:
- **Label:** `y = 1 if winner == 'A' else 0`

From `model_features.build_match_features`:
- `rank_diff = rank_B - rank_A`
- `log_points_diff = log(1+points_A) - log(1+points_B)`
- `seed_diff = seed_B - seed_A`

Therefore:
- **Does y=1 mean Player A wins?** Yes.
- **Does positive rank_diff mean Player A is stronger?** Yes (better = lower rank number).
- **Does positive log_points_diff mean Player A is stronger?** Yes.
- **Does positive seed_diff mean Player A is stronger?** Yes (better = lower seed).

## 4. SYSTEMATIC CONTRADICTION TEST (full dataset)

Computed across all usable rows in `historical_2026_v3.csv`:

| Metric | Value |
|---|---:|
| % rows where A has **better rank** but **loses** | **15.22%** |
| % rows where A has **more points** but **loses** | **15.22%** |
| % rows where A has **better seed** but **loses** | **9.62%** *(only 52 seeded rows usable)* |

Conditioned on label:

| Condition | A better rank but loses | A more points but loses | A better seed but loses |
|---|---:|---:|---:|
| winner == A | 0.00% | 0.00% | 0.00% |
| winner == B | 30.77% | 30.77% | 21.74% |

**Sanity interpretation:**
- The unconditional rates (15–16% for rank/points) look plausible for tennis upsets in a short window.
- The “winner==A” conditional being 0% is expected because “A loses” is impossible in that subset (it’s a definition artifact of the conditioning as implemented).
- Importantly: there is **no evidence** here that ranks/points are systematically swapped between A and B.

## 5. SIGN CHECK BY FEATURE (univariate)

Univariate logistic regression on the built CSV (train/test split, AUC reported):

| Feature | coef sign | AUC | n used |
|---|---:|---:|---:|
| `rank_diff` | **+** (0.0077) | 0.7196 | 552 |
| `log_points_diff` | **+** (0.8747) | 0.7396 | 552 |
| `seed_diff` | **+** (0.1242) | 0.95 | 52 |

**If a multivariate model learns a negative `rank_diff` coefficient, this audit indicates it is not because rank columns are swapped in the CSV**; more likely causes are collinearity, missingness interactions, or downstream feature/label artifacts outside these columns.

## 6. RAW SOURCE VS BUILT CSV CHECK

Raw source schema expected by the builder:
- `winner_name`, `loser_name`
- `winner_rank`, `loser_rank`
- `winner_rank_points`, `loser_rank_points`
- `winner_seed`, `loser_seed`
- plus tourney/date/surface/score/round and optional v3 fields.

Builder mapping:
- If `swap=False`, A is the **winner** and `winner='A'`, with A’s rank/points/seed sourced from `winner_*`.
- If `swap=True`, A is the **loser** and `winner='B'`, with A’s rank/points/seed sourced from `loser_*`.

This mapping is internally consistent by construction. To do a strict record-level trace, add a stable match identifier (e.g. `tourney_id + match_num + date + winner_name + loser_name`) and log the raw row index during build. (Recommended in §9.)

---

## 7. DUPLICATE / MIRROR CONSISTENCY

In the **builder output CSV**, there are **no guaranteed mirrored pairs**: each raw match row produces exactly one output row with random `swap`. Therefore a “find both A/B orientations” check on `historical_2026_v3.csv` will typically find **0 mirrored pairs** (observed `pairs_checked = 0` in this audit).

Mirroring is enforced later during training by `model_train.load_historical_csv(..., mirror_rows=True)`, which creates a synthetic swapped row and inverts the label.

---

## 8. ROOT CAUSE (for negative `rank_diff` observed in some fits)

Based on this audit of the built CSV:
- **Not** a swapped rank/points column issue in `build_historical_from_tml.py` (univariate signs are positive; AUCs sensible).
- **Not** a wrong formula (rank_diff/log_points_diff/seed_diff formulas verified).
- Most likely explanations for wrong-sign `rank_diff` in a multivariate trained model:
  - **collinearity / redundancy** with `log_points_diff` and seed features on a small dataset slice,
  - strong missingness patterns interacting with mirroring,
  - event/context features dominating and forcing compensation,
  - training on a narrow, non-stationary period (short window 2026-01 to 2026-03).

If a negative `rank_diff` persists on a large multi-year dataset with minimal feature set, then suspect downstream label/order artifacts elsewhere.

## 9. FIX (builder hardening + permanent validation gate)

### Implemented: builder alignment validation

`scripts/build_historical_from_tml.py` now supports:
- `--validate-alignment` to run sanity checks after generation
- `--min-win-signal` (default 0.55)

Validation logic (high level):
- Among rows where `winner=='A'` and rank is present, require that `rank_diff > 0` at least `min_win_signal` fraction of the time (with enough rows).
- Similarly for `log_points_diff > 0`.
- Fail hard if thresholds are violated (strong indicator of A/B swaps).

### Recommended permanent additions (next)
- Add a stable match id to output (e.g. `match_id = f\"{tourney_id}:{tourney_date}:{winner_name}:{loser_name}\"`) so raw→built tracing is trivial.
- Add a “schema guard” that checks required raw columns exist and errors if the input is not a TML-style file.
- Optionally, add `--write-audit` to output summary stats (the same ones in `scripts/dataset_alignment_audit.py`) alongside the built CSV.
